# tdl-GUI 需求书（proposal）

> 版本：v0.3（登录功能并入设置选项卡，导航栏缩减为 4 个入口；含两项交互硬性要求：开始按钮→红色中止按钮切换、任务执行期间导航栏与全部任务参数锁定变灰，详见 §4.1）
> 日期：2026-09-19
> 参考文档：https://docs.iyear.me/tdl/（tdl 官方文档，本文所有命令行用法均以此为准）

---

## 1. 项目概述

为命令行工具 `tdl`（Telegram Downloader/Toolkit）开发一个 Windows 桌面 GUI 前端。

- GUI **不重新实现** tdl 的任何功能，仅作为命令构造器与运行器：将界面参数拼装为 tdl 命令行，调用 `tdl.exe` 子进程执行，并实时回显其输出。
- 打包产物为**单个 exe**（不含图标资源等附属文件）。
- 软件内所有设置持久化，使用 **Fyne 内置 Preferences** 存储（由框架管理于系统应用数据目录），**不产生任何用户可见/需维护的 json 配置文件**。

### 已确认的设计决策

| 决策点 | 结论 |
|---|---|
| tdl.exe 集成方式 | 不打包、不内嵌。在**设置页由用户自行选择 tdl.exe 路径**（文件选择器），路径持久化 |
| 设置持久化方案 | Fyne Preferences（`fyne.CurrentApp().Preferences()`） |
| 登录方式 | 仅支持**桌面客户端登录**（`tdl login`，即从 Telegram Desktop 会话导入；不支持二维码/验证码方式） |

| 项 | 选择 | 说明 |

## 3. 功能范围（做 / 不做）

**做：**
1. **Download**：`tdl dl` 全部参数；含"从 txt 文件读入（每行一个链接）"的批量下载
2. **Upload**：`tdl up` 全部参数
3. **Tools / Export Messages**：简单版 `tdl chat export`
4. **设置页**：tdl.exe 路径 + 全局参数 + **登录管理（Login：简单多账户/命名空间，仅桌面客户端登录；原独立登录选项卡并入设置页）**

**不做：** Forward（转发）、Migration（迁移）、List Chats、Export Members、Extensions、tdl 的 serve 模式以外的其他一切功能均不实现（serve 模式属于 download 参数集，见 §5.1）。

## 4. 界面总体设计

```
┌──────────┬─────────────────────────────────────────────┐
│          │  [运行日志]（黑框，固定常显，所有选项卡共享）      │
│  左侧     │  ─ 实时滚动显示 tdl.exe 输出与任务进度            │
│  导航栏   │  ─ 显示每次执行的完整命令行                       │
│          ├─────────────────────────────────────────────┤
│  下载     │                                             │
│  上传     │   当前选项卡的参数编辑区                        │
│  导出消息  │   （各可设置参数按顺序自上而下排列，             │
│  设置     │     底部为 [开始] 按钮——任务运行时               │
│ （含登录） │     立即变为红色 [中止] 按钮）                   │
└──────────┴─────────────────────────────────────────────┘
```

### 4.1 布局规则

- 左侧导航栏：4 个入口 —— **下载 / 上传 / 导出消息 / 设置**。登录功能不再单独成页，位于设置选项卡内部（见 §5.4）。
- 右侧区域垂直切分为两部分：
  - **上部（固定，跨选项卡常显）**：运行日志黑框。无论切换到哪个选项卡，日志区始终显示在最上方，内容全局共享、连续累积。
  - **下部**：当前选项卡的参数表单，各项参数按本文件 §5 定义的顺序自上而下排列；底部为任务操作按钮行（[开始]/红色 [中止]，见下方任务模型）。
- 日志黑框：
  - 黑底浅色字（等宽字体），实时流式输出 tdl 子进程的 stdout 与 stderr（合并显示）。
  - 处理进度条刷新：tdl 输出使用 `\r` 回车刷新进度行，GUI 需在日志框内**行内更新**该行而非追加新行。
  - 过滤/剥离 ANSI 转义序列（颜色码等），保证可读。
  - 每次执行前先回显一行完整命令行（含全局参数），便于核对。
  - 提供：自动滚动到底部（可暂停）、**清空**、**复制全部**。
- 任务模型：**同一时刻仅允许一个运行中的 tdl 子进程**。
- **[开始]→红色 [中止] 按钮切换（硬性要求）**：每个任务触发按钮（下载/上传/导出消息页底部的 [开始]，设置页内登录区的各操作按钮与 [测试] 按钮）在用户单击启动任务后，**该按钮立即变为红色的 [中止] 按钮**；任务结束（正常完成/失败/被中止）后恢复为原按钮。
- **执行期间全局锁定（硬性要求）**：任一任务开始执行后，**左侧导航栏所有选项卡与右侧全部任务参数控件一律禁用（变灰、不可交互）**，页面内其余任务按钮亦禁用；期间唯一可交互的任务控件是红色 [中止] 按钮。锁定持续到任务完成或用户单击 [中止] 杀死进程为止，随后全部恢复可交互。
- **中止语义**：单击 [中止] 必须**立刻杀死任务进程**——Windows 下使用 `taskkill /T /F` 或 Job Object 连同整棵进程树强制终止，不等待其自行退出；日志中醒目标注"已中止"。
- 例外说明：日志区的清空/复制/自动滚动控制不属于导航选项卡或任务参数，运行期间保持可用（便于运行中留存日志）；如需完全锁定可收紧。

## 5. 各选项卡需求明细

> 以下参数均与 tdl 官方文档一一对应。除注明默认值外，未填写/未勾选的参数**不拼入**命令行。
> 命令拼装格式：`<tdl.exe路径> [全局参数(§5.4)] <子命令> [子命令参数]`。
> 各选项卡的全部表单字段在修改后立即写入 Preferences，重启后恢复上次值。

### 5.1 下载（`tdl dl`）——"全部功能"

**输入源（三选多，可组合）：**

| UI 元素 | 对应参数 | 说明 |
|---|---|---|
| 链接多行输入框 | `-u <link>`（每行一个，生成多个 `-u`） | 支持 t.me 各式链接：`https://t.me/telegram/193`、`https://t.me/c/1697797156/151`（私有）、话题范围 `https://t.me/iFreeKnow/45662/55005`、评论区 `...?comment=...`、讨论串 `...?thread=...` |
| **txt 批量导入**：[选择 txt 文件] 按钮 + 已选文件路径显示 | （GUI 适配层）读取 txt，**每行一个链接**，全部展开为多个 `-u`，与链接输入框内容合并 | tdl 原生 `-f` 只接受 JSON；txt 逐行链接由 GUI 读取后转为多个 `-u` 实现。读取时跳过空行与 `#` 开头注释行；导入后在 UI 显示"已解析 N 条链接"并可在日志中列出清单 |
| tdl 导出 JSON 文件（可多个） | `-f <file>`（多个文件 → 多个 `-f`） | 用于接收 export-messages 产物；列表式 UI，支持添加/移除多个文件 |

**参数（自上而下排列）：**

| 参数 | UI | 对应 flag |
|---|---|---|
| 下载目录 | 目录选择器 | `-d <dir>` |
| 每任务线程数 | 数字输入（留空=默认） | `-t <n>` |
| 并发任务数 | 数字输入（留空=默认） | `-l <n>` |
| 降序下载（最新→最旧） | 勾选框 | `--desc` |
| MIME 扩展名重写 | 勾选框（附提示：如 .apk 会被改名 .zip） | `--rewrite-ext` |
| 自动下载相册/分组 | 勾选框 | `--group` |
| 跳过同名且同大小文件 | 勾选框 | `--skip-same` |
| 使用 Takeout 会话 | 勾选框（附提示：大量下载时可减少 flood wait） | `--takeout` |
| 扩展名白名单 | 文本框（逗号分隔，如 `jpg,png`） | `-i <exts>` |
| 扩展名黑名单 | 文本框（逗号分隔，如 `mp4,flv`） | `-e <exts>` |
| 文件名模板 | 文本框（变量如 `{{ .DialogID }}`、`{{ .MessageID }}`、`{{ .FileName }}`） | `--template` |
| 断点策略 | 单选：默认（无附加）／续传／重新开始 | 续传 → `--continue`；重新开始 → `--restart`。默认模式下 tdl 检测到未完成任务会交互询问，而 GUI 子进程无 stdin 输入，因此需用户显式选择 |
| serve 模式 | 勾选框 + 端口数字输入（默认 8080） | `--serve`、`--port <n>`（勾选 serve 时才拼入 port） |

**校验：** 白名单与黑名单**不能同时填写**（同时填写时 [开始] 禁用并提示）；输入源（链接框 + txt + json）至少有一项非空才可执行。

### 5.2 上传（`tdl up`）——"全部功能"

| 参数 | UI | 对应 flag |
|---|---|---|
| 待上传文件/目录 | 列表式多选（添加文件/添加目录/移除），至少一项 | `-p <path>`（多个） |
| 目标聊天 | 文本框，支持 `@iyear` / `iyear` / `123456789` / `https://t.me/iyear` / `+1 123456789`；留空 = Saved Messages | `-c <chat>` |
| 论坛话题 ID | 数字输入（需配合目标聊天） | `--topic <id>` |
| 消息路由 | 文本框（表达式或路由文件路径）；**与目标聊天/话题互斥** | `--to` |
| 每任务线程数 | 数字输入 | `-t <n>` |
| 并发任务数 | 数字输入 | `-l <n>` |
| 标题（caption） | 多行文本框（表达式或文件路径） | `--caption` |
| 扩展名白名单 | 文本框（逗号分隔） | `-i <exts>` |
| 扩展名黑名单 | 文本框（逗号分隔） | `-e <exts>` |
| 上传成功后删除本地文件 | 勾选框（附醒目警示） | `--rm` |
| 图片以照片形式发送 | 勾选框 | `--photo` |

**校验：** 白/黑名单互斥同上；消息路由与（目标聊天或话题）互斥，冲突时 [开始] 禁用并提示。

### 5.3 导出消息（`tdl chat export`）——"简单版"

| 参数 | UI | 对应 flag |
|---|---|---|
| 目标聊天 | 文本框（格式同上传的 `-c`；留空 = 收藏夹） | `-c <chat>` |
| 话题 ID | 数字输入（可选） | `--topic <id>` |
| 评论区帖子 ID | 数字输入（可选） | `--reply <id>` |
| 输出文件路径 | 文件保存选择器（默认 `tdl-export.json`） | `-o <path>` |
| 导出类型 | 单选：按时间（默认）/ 按消息 ID / 最近 N 条 | `-T time` / `-T id` / `-T last` |
| 范围 | 文本框：时间为 `起,止` Unix 时间戳；ID 为 `起,止`；last 为数量 N | `-i <range>` |
| 过滤表达式 | 文本框（可选，如 `Views>200 && Media.Name endsWith '.zip'`） | `-f <expr>` |
| 附带消息内容 | 勾选框 | `--with-content` |
| 导出全部消息（含非媒体） | 勾选框 | `--all` |
| 原始 MTProto 结构 | 勾选框（标注"调试用"） | `--raw` |

导出的 JSON 可直接作为下载页 `-f` 的输入（形成"导出→下载"工作流）。

### 5.4 设置（全局参数 + 登录管理）

设置选项卡自上而下分为两个区块：**5.4.1 全局参数**、**5.4.2 登录管理**（登录功能并入设置，不再单独成页）。
以下全局 flag 按官方文档**不持久化于 tdl**（每次命令都要带），因此由 GUI 保存并在每次执行命令时自动附加。

#### 5.4.1 全局参数

| 参数 | UI | 对应 flag | 默认 |
|---|---|---|---|
| **tdl.exe 路径** | 文件选择器（必填） | （子进程路径本身） | 无 |
| 当前命名空间（账号） | 文本框/下拉（与下方登录管理联动） | `-n <ns>` | `default` |
| 代理 | 文本框（`protocol://user:pass@host:port`，如 `socks5://localhost:1080`） | `--proxy` | 空 |
| NTP 服务器 | 文本框 | `--ntp` | 空 |
| 重连超时 | 文本框（如 `2m`、`1m30s`） | `--reconnect-timeout` | `2m` |
| DC 连接池大小 | 数字输入 | `--pool` | 8 |
| 任务间延迟 | 文本框（如 `5s`） | `--delay` | `0s` |
| 调试模式 | 勾选框 | `--debug` | 关 |
| 禁用进度条 CPU/内存统计 | 勾选框 | `--disable-progress-ps` | 关 |
| 存储（高级） | 文本框（`type=DRIVER,opt=val,...`，一般用户保持默认） | `--storage` | 空（不拼入，即 tdl 默认 `type=bolt,path=~/.tdl/data`） |

**首次启动：** 未设置 tdl.exe 路径时，自动跳转设置页并提示选择；路径未设置前所有功能页 [开始] 按钮禁用。设置页提供 [测试] 按钮：执行 `<tdl.exe 路径> --version`（或等价的轻量命令）验证可用性，结果显示于日志框。[测试] 亦视为一个任务，同样遵循 §4.1 的开始/中止按钮切换与全局锁定规则。

#### 5.4.2 登录管理（多账户，仅桌面客户端登录）

多账户通过 tdl 的**命名空间（namespace，`-n`）**实现，每个命名空间即一个账号。

| 功能 | UI | 命令 |
|---|---|---|
| 登录新账户 | 命名空间文本框（必填，如 `default`、`work`）+ 本地密码输入框（可选，对应客户端"本地密码"）+ 客户端目录选择器（可选，自定义 Telegram Desktop 安装路径） | `tdl -n <ns> login [-p <passcode>] [-d <dir>]` |
| 列出已登录账户 | 按钮 | `tdl login -l`（输出显示于日志框） |
| 切换默认账户 | 命名空间下拉框（手填或沿用上次列表）+ [设为默认] 按钮 | `tdl use -n <ns>` |
| 登出 | 命名空间输入 + [登出] 按钮 | `tdl -n <ns> logout` |

**说明：**
- 仅做桌面客户端登录（tdl 默认方式：读取 Telegram Desktop 会话数据）。UI 需提示：客户端须从官网下载（非 Microsoft Store / App Store 版本）。
- 其余功能页执行命令时，统一带上 5.4.1 中设置的当前命名空间 `-n <ns>`。
- 登录区各操作按钮（登录/列出/设为默认/登出）均为任务触发按钮，遵循 §4.1 的开始/中止切换与全局锁定规则：由哪个按钮发起的任务，哪个按钮变为红色 [中止]。

## 6. 命令拼装规则（GUI → CLI 映射汇总）

```
<tdl.exe> -n <ns> --proxy <p> --ntp <h> --reconnect-timeout <t> --pool <n> --delay <d>
         [--debug] [--disable-progress-ps] [--storage <s>]
         <dl | up | login | logout | use | chat export>  <子命令flags...>
```

- 设置页登录区命令（`login`/`use`/`logout`）按 §5.4.2 各自独立拼装。
- 布尔参数：勾选才拼入；数值/文本参数：非空才拼入。
- 数字输入非法（非正整数等）时即时红框提示并禁用执行。
- 拼装完成的完整命令行在日志框回显后再启动子进程。

## 7. 进程与日志（核心机制）

1. `exec.Command(tdlPath, args...)`，`cmd.Stdout`/`cmd.Stderr` 指向同一个管道合并输出。
2. 后台 goroutine 持续读取输出，按 `\n`/`\r` 解析：
   - `\r` 结尾的行视为进度刷新 → 更新日志框中对应"当前任务行"；
   - `\n` 结尾的行 → 追加新行。
3. 剥离 ANSI 转义序列后再写入 `TextGrid`。
4. UI 更新通过 Fyne 主线程 API（`fyne.Do` / data binding）保证线程安全。
5. 中止实现：单击红色 [中止] 按钮后**立即**强制杀死进程树（`taskkill /T /F` 或 Job Object），不等待优雅退出，随后日志醒目标注"已中止"。
6. 进程退出后（正常完成/失败/被中止）日志框输出退出码并醒目标注，随后解除全局锁定（§4.1），按钮恢复为 [开始]。
7. 环境变量继承用户系统环境（PATH 等），不额外设置。

## 8. 持久化方案

- 存储：`fyne.CurrentApp().Preferences()`，键名按 `<选项卡>.<字段>` 规划（如 `download.dir`、`upload.paths`、`settings.tdlPath`）。
- 多值字段（上传文件列表、json 文件列表、链接框内容）：以换行符拼接为单字符串存储（Preferences 原生不支持切片）；不落任何 json 文件。
- 保存时机：字段变更即写（onChanged 回调），无需"保存"按钮。
- 迁移/导出设置功能：**不做**。

## 9. 非功能需求

- 平台：Windows（win32）；打包为单文件 exe（Fyne 依赖 CGO/MinGW 工具链构建）。
- 运行依赖：用户自备 tdl.exe（任意版本，路径在设置页指定）与 Telegram Desktop（仅登录时需要）。
- 窗口建议尺寸 1000×640，可缩放；日志框高度约占右侧 40%，参数区可滚动。
- 软件不读写 tdl 的数据目录（`~/.tdl`），不干扰 tdl CLI 独立使用。

## 10. 验收标准

1. 产物为单个 exe，双击可运行；本机除 tdl.exe 外无需任何其他文件。
2. 设置 tdl.exe 路径后重启软件，路径与全部表单参数均保留（无任何 json 等配置文件出现在软件目录）。
3. 下载页：手动链接、txt 批量（每行一个链接）、tdl JSON 三种输入源可单独或组合使用；txt 含空行/注释行时正确跳过；日志正确显示进度条实时刷新。
4. 上传页：全部 flags 可用，路径可多选；`--rm` 有二次确认弹窗。
5. 设置页登录区：可用不同命名空间登录 ≥2 个账户，`login -l` 可列出，`use` 可切换，`logout` 可登出；其他页面执行时自动携带当前命名空间。
6. 导出消息页：三种范围类型（time/id/last）均可执行并产出 JSON，该 JSON 可被下载页 `-f` 直接使用。
7. 任务运行中：单击 [开始] 后该按钮**立即变为红色 [中止]**；运行期间**导航栏全部选项卡与全部任务参数控件变灰不可交互**（唯一可交互的任务控件为 [中止]）；单击 [中止] 后 tdl 进程树被**立即杀死**（日志标注"已中止"），或任务正常结束后，界面全部恢复可交互；日志区跨选项卡常显且内容连续。
8. 白/黑名单互斥、路由与聊天互斥、非法数字等校验生效，冲突时给出明确提示。

## 11. 风险与注意事项

| 风险 | 对策 |
|---|---|
| tdl 交互式确认（未完成任务时等待 stdin） | 下载页提供 `--continue`/`--restart` 显式选择（§5.1） |
| 进度条 `\r`/ANSI 渲染异常 | 解析器 + 转义剥离；必要时对该类行做整行替换 |
| tdl 版本更新导致 flag 变化 | 以官方文档为准；命令行拼装集中在一个独立模块（`cmdgen`），便于适配 |
| Fyne Windows 构建 CGO 依赖 | 构建环境需 MinGW-w64；交付物仅为 exe，用户侧无感知 |
| `--rm` 误删本地文件 | 执行前二次确认弹窗 |
| Windows 下强杀进程树（中止必须"立刻"生效） | 使用 `taskkill /T /F` 或 Job Object 保证整棵进程树彻底、立即退出 |
